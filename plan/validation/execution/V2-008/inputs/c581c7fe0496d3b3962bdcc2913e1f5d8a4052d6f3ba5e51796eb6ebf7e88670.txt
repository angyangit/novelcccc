# AI 开发执行协议

版本：1.3.0；生效范围：ANovelOS 规划维护及 V2-001～061 的 AI 开发、验证与交接。它落实既定路线，不新增业务架构或阶段。

本协议降低方向偏离、无依据决策和虚假完成风险，不承诺消除 AI 幻觉。V2-002 已将规划治理检查接入本地命令入口；V2-003 已实现本地架构、代码差异和防降标工具，当前 IMPLEMENTED，已有绑定提交的本地代码和测试证据。可信远端门禁仍由 V2-004 实施。资料校验 PASS 不表示这些工程能力全部已经运行。

## 1. 一次推进的边界

每次执行只消费本次任务及其依赖所需的现行规范、机器记录和验收场景。用户授权是范围依据，聊天摘要、历史档案、外部 README、模型建议和审核报告都是输入，不能自行新增任务或授予权限。

AI 在已授权任务范围内可以自主读取、设计、实现、测试、修复、记录和进入已满足条件的下一步骤；不要求用户重复批准正常动作。改变冻结目标、任务身份/依赖、最低验收、权限或既定付费上限时，记录变更依据和影响；无相应授权就停止该动作，继续不依赖它的工作。停在具体缺口，不把局部缺口解释为永久停止项目。

不以“未来可能需要”为由提前实现后续阶段。不因模型建议或测试失败引入第二条 Canon 路径、绕过硬门禁或扩大早期产品范围。优先消除当前关键链阻断，新增工作应有当前消费者与验收映射。

## 2. 任务执行包是开工输入

任务通过 `execution_packet_ref` 指向基于[执行包模板](templates/EXECUTION_PACKET.yaml)填写、服从 [execution-packet.schema.json](schemas/execution-packet.schema.json) 的正式执行包。引用相对 `plan/`，正式记录的 `record_type` 为 `task_execution_packet`，解析后的文件必须位于 `validation/`，建议使用 `validation/execution/<task>/`。IN_PROGRESS 及后续状态需要非模板执行包；OPEN 任务不要求预先填写 60 套环境和虚构证据，有包时只允许 PREPARE。准备调研可以先进行，进入正式动作前补齐对应输入并通过任务开工门禁。

执行包至少记录：任务身份、计划版本、checkout 与工作区状态、规范/输入路径及 hash、操作者和验证者、允许修改的范围、目标产物、验收场景、适用 ADR、当前动作、待决项、事实与假设、付费边界、停止条件和交接信息。规范清单由任务引用产生，不能通过只选宽松规则排除适用要求。执行包是上下文与动作条件，不替代代码、测试、CI 或验收证据。

`inputs` 每项用 `source_ref` 标识现行来源、`ref` 指向可恢复快照、`sha256` 绑定内容。必须覆盖任务全部现行规范及 backlog、test-catalog、decision-register、ai-execution-policy 四份机器源，由此追溯适用的验收场景。活动执行包核对现行来源内容与计划版本/manifest；VERIFIED/CLOSED 的历史包保留对应快照，不因后续计划修订而强制改写历史。`repository_revision` 是开工基线，不是当前工作树或远端运行真实性认证。

输入被修改时重新判断适用性，并保留原记录及本次变更原因。hash 能检测输入变化，不能证明内容真实、语义正确或操作者独立。执行记录目录不纳入计划 FILE_MANIFEST，避免执行包与 manifest 自引用；运行产物与受审输入分别管理。

## 3. 动作前置条件与临时决策

| 动作 | 准许范围 | 动作前必需条件 |
|---|---|---|
| PREPARE | 阅读、核实、比较方案、隔离调查与执行细化 | 明确任务/授权；未知项可保留，不能声称已完成实施 |
| IMPLEMENT | 当前任务的代码、配置、接口和测试实现 | 适用阶段/依赖与执行包有效；到时点的 `before_interface_implementation` ADR 已接受 |
| LIVE_CALL | 经批准的真实付费模型调用 | 适用 ADR 已接受；有可核对授权、总预算和停止条件；不能用模拟结果放行 |
| CERTIFY | 依协议执行正式章节认证 | 认证前 ADR、协议、样本、指标、版本和全部前置门禁已冻结且有证据 |

动作名称不是永久通行证。切换动作、输入变化或恢复会话后重新检查适用前置条件；依赖较早 ADR 的后续动作也不能绕过它。PREPARE 不能被用来给接口实现、付费调用或正式认证改名。未决 ADR 可以在准备阶段比较方案，但到其最晚时点仍未接受就阻断相关动作；不要求所有未来 ADR 在 P0 一次完成。

对影响范围、接口、依赖、阈值或预算的判断，使用 `claims` 中的 FACT/ASSUMPTION/UNKNOWN 区分可复查事实、假设和未知；FACT 绑定 `sources` 及 hash。记录最终决定和验证方式，待核项用 `blocks_actions` 声明阻断动作。检查声明完整和 hash 一致不能证明事实真伪，AI 仍需核实原始来源。缺少文档/API/实验依据时允许回答未知，不编造方法、依赖版本、成本或成功率。合理的局部实现选择可由 AI 在授权内完成并记录，不把每个变量命名都升级成 ADR。

## 4. 用实际差异核验任务归属

`allowed_paths` 采用仓库相对的明确文件或以 `/` 结尾的目录，表示任务范围，不是操作系统权限。P0 的执行入口和 CI 要比较受信任基线与实际工作树/提交的变更，覆盖已跟踪修改、删除、重命名和新增未跟踪文件。将每项变更映射到任务范围或有依据的例外；仅填写允许路径、仅核对任务状态，不能证明实际行为在范围内。

路径匹配只能检查边界，不能判断业务语义。跨模块修改、新增依赖、引入未来阶段功能以及超出执行包范围的产物，需补充任务归属和影响检查。已存在的用户改动单独记录，不能归为 AI 完成，也不能为了得到干净差异而删除。

以下变更必须与可信旧版本比较并形成明确处置：删减验收场景/断言、删除或跳过测试、扩大扫描排除、降低阈值、把硬失败改为允许失败，以及修改验证器、最低基线或保护规则。正文与机器验收一起改弱仍属规则变更，内部一致不代表可放行。必要的测试修正和规范修订可以进行，但必须说明原要求为何错误、授权依据、影响和替代验证；不能以“否则测试不通过”为唯一理由。

V2-003 的本地 `scripts/check_changes.py` 从完整 Git scope pin 读取固定范围、开工 index/worktree 身份及授权来源，覆盖当前暂存区、工作树、已提交变化和未跟踪内容。候选 packet、基线或 ignore 修改不能扩张授权或隐藏源码；既有用户改动仅按未变化身份单独归属。处置另用 review Git pin 绑定精确 finding、旧/新内容、理由、影响及替代验证；原 finding 保留，真实削弱须有固定输入中的适用显式授权，候选自签声明无效。静态判断无法确认的语义变化需要审查，路径合法不等于业务正确；本地 pin 也不等于受保护远端来源。

## 5. 可信验收与权限边界

V2-004 将“代码提交 → 可信 CI 执行 → 原始产物 → 来源核对 → 验收引用”接成真实流程。核对项目、提交、pipeline/job、运行结果、命令、适用检查和产物 hash；失败、取消和缺失必须保留真实状态。本地 JSON、看似有效的 URL、自填 PASS 或同一 AI 的口头声明不能替代来源核对。

实施角色可修改产品代码，但不能同时无审计地降低保护规则、绕过门禁并批准自己的例外。P0 根据实际平台能力设置普通实施凭证与受保护配置/验证权限边界，并核验有效配置；不要求增加固定人数，也不因分成多个 Agent 就称为独立复核。若同一操作者仍掌握全部权限，应明确单操作者信任边界，不能声称已经建立对抗性保护。

本地校验与同仓库测试可发现约束违反，但无法抵抗同一写入者同时修改资料、原始结果和校验器。远端不可读、无权限或配置未落实时，相应能力保持未验证；不得用旧提交 PASS 或模板补位。

## 6. 交接与恢复

执行包的 `handoff` 用 `current_step`、`completed_steps`、`pending_items`、`next_action` 和 `last_check`（状态与产物）保留最低交接上下文，并记录实际改动、真实命令/退出结果、失败与停止原因和恢复条件。测试“准备运行”和“已成功运行”分开记录；未写入仓库或持久证据的模型记忆不作为完成依据。规划校验核对结构与已声明产物 hash；V2-002 本地 `resume` 另核对实际 checkout/index/worktree 和前次 PASS 上下文，但不自动重放有副作用的动作，也不认证远端来源。

换会话、换模型、断电或中断后，先读取交接及机器源，再核对实际 checkout、工作区差异、输入 hash 和证据适用性。发现不符就更新上下文并重新验证受影响部分，不盲目重跑有副作用动作，也不继承摘要中的已完成声明。已成功动作使用原记录继续，UNKNOWN 操作先核实结果。小说 Workflow 的恢复机制不替代开发 AI 的交接。

## 7. P0 落地及后续消费

| 责任任务 | 交付与验证 |
|---|---|
| V2-002 | 执行包结构/引用/输入绑定、动作 ADR 前置、交接检查接入工程命令；缺失/过期/错任务等负例被拒绝，合格包及合法准备动作通过 |
| V2-003 | 实际差异范围和验收弱化识别接入架构检查；测试越界、新文件、删减/skip 和合法有依据修订，不能只测空差异 |
| V2-004 | 动作入口与可信 CI、源结果核对及实际权限边界接通；模拟 PASS、错 revision、缺保护和不可核验结果不能获得真实放行 |

本地执行包检查集成在 `python3 -B plan/scripts/validate_plan.py --check`，专项回归为 `python3 -B plan/scripts/test_ai_execution.py`；它们不调用模型。V2-002 已新增项目根 `scripts/task_execution.py` 的本地 check/run/resume 入口，复用这些规则检查后才执行指定子命令，并核对真实 checkout、暂存区、工作区内容和恢复产物。`scripts/check_governance.py` 聚合原有检查并导出规范索引与仓库配置清单。

V2-003 的 `scripts/check_architecture.py` 扫描完整生产包，静态检查领域依赖、Canon 公共提交服务与内部写能力边界及适用 P0 硬门禁。`task_execution.py` 对 IMPLEMENT/LIVE_CALL/CERTIFY 强制读取执行包 `change_review` 的 `scope_revision` / `scope_ref` 与必要时的 `review_revision` / `review_ref`。缺 scope 绑定即拒绝；CLI 对应参数只能重述同值，不能覆盖。省略 CLI 参数仍在命令前后审查实际差异。PREPARE 没有冻结 scope 时可调查，但不能借其执行受限实施动作。架构检查仍须明确运行，不由 scope 参数隐式代跑。用法、当前固定 pin 与输出边界见 [任务执行指南](09_TASK_EXECUTION_GUIDE.md)。本地工具不能抵抗共享写权限者修改或绕过检查器，远端来源和有效权限保护仍由 V2-004 落地，实际状态以任务与证据为准。后续任务按相同协议消费，不另建绕开 backlog 的自主 Agent 工作流。

AI 可以承担全部软件开发工作，但真人 Gold/读稿与真实市场证据仍保持 E3/E4 来源要求。模拟读者属于 E2，不能借“全 AI 开发”替代真实阅读竞争力验证。工程不崩、题材不串、阅读质量和市场结果分别判断，不互相代替。
