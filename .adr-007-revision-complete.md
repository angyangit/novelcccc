### ✅ Requirement 4: Project Binding Traceability
**Issue**: Binding must have traceable, recoverable records; reuse Canon mechanism

**Resolution**:
- **V2-013 scope**: In-memory dict (satisfies AT-V2-013 acceptance)
- **Future persistence**: Reuse Canon commit mechanism (ADR-006)
  - Binding as Canon event: `PROJECT_GENRE_BINDING_CREATED`
  - Persist via `CanonCommitService.commit()`
  - Reuse existing `canon_commit` and `canon_event` tables
- **No new systems**: No second commit system, no unauthorized DB schema
- **Traceable record**: project_id, pack_identity, bound_at, binding_hash
- **Recoverable**: From Canon event stream using binding_hash

**Location**: ADR-007 lines 426-470 (绑定记录可追溯性与恢复)

---

### ✅ Requirement 5: Pack ID and Version Semantics
**Issue**: Unify Pack ID/Version semantics, use two frozen Anchors, prevent duplicate identifiers

**Resolution**:
- **pack_id**: NO version suffix (e.g., `urban.business.realistic`)
- **version**: Separate semantic version field (e.g., `1.0.0`)
- **Two frozen Anchors**:
  - Pack ID: `urban.business.realistic`, Version: `1.0.0`
  - Pack ID: `fantasy.eastern.progression`, Version: `1.0.0`
- **Validation**: Reject pack_id with `.v*` suffix in `__post_init__`
- **Prevents**: Duplicate version identifiers like `urban.business.realistic.v1` + version `1.0.0`

**Location**: ADR-007 lines 30-44 (Pack Identity), V2-013 lines 79-91 (GenrePackIdentity validation)
